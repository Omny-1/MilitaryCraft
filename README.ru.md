# MilitaryCraft

[English](README.md) · Уззкий · [Українська](README.ua.md)

[![Build](https://github.com/Omny-1/MilitaryCraft/actions/workflows/build.yml/badge.svg)](https://github.com/Omny-1/MilitaryCraft/actions/workflows/build.yml)

MilitaryCraft - это один плагин для Paper, который добавляет в Minecraft 1.21.4 управляемую
технику, авиацию, стационарные огневые точки, авиационную поддержку и набор пехотного
снаряжения. Всё построено на ванильных display-сущностях и обычных вызовах серверного API,
поэтому серверу не нужен ни клиентский мод, ни дополнительные плагины.

## Требования

| Пункт | Значение |
| --- | --- |
| Серверное ядро | Paper 1.21.4 или новее |
| Проверенный диапазон | с 1.21.4 по 1.21.8 |
| Java | 21 |
| Зависимости | Нет |
| Folia | Не поддерживается |

Плагин собран под Paper API. Spigot и CraftBukkit не поддерживаются, потому что несколько
модулей используют вызовы, которых нет за пределами Paper. Folia явно помечена как
неподдерживаемая в `plugin.yml`, так как планировщики модулей рассчитаны на один основной
поток.

## Установка

1. Скачайте или соберите `MilitaryCraft-1.0.0.jar` (см. [Сборка из исходников](#сборка-из-исходников)).
2. Положите jar в папку `plugins` на сервере.
3. Запустите сервер один раз. При первом запуске создаётся `plugins/MilitaryCraft/config.yml`.
4. При необходимости измените настройки, затем выполните `/mc reload` или перезапустите сервер.

Ресурспак необязателен и описан в отдельном разделе ниже. Без него все предметы выглядят
по-ванильному, но все функции работают в полном объёме.

## Первые шаги

По умолчанию команды MilitaryCraft доступны только операторам сервера. От имени оператора:

```text
/mc menu           открыть графическое меню команд
/mc modules        показать все модули и их состояние
/tank give         получить предмет для установки танка
/tank spawn        поставить танк на своей позиции
/warkit giveall    получить всё пехотное снаряжение
```

Почти вся техника работает одинаково. Командой `give` вы получаете предмет-установщик,
ставите его как блок, затем правым кликом садитесь в технику. Команда `spawn` создаёт
технику сразу, без предмета, а `place x y z [мир]` делает то же самое по точным координатам
и работает в том числе из консоли сервера.

Как убрать созданное:

```text
/tank remove       убрать танк, на который вы смотрите
/tank cleanup      убрать оставшиеся сущности танков
/mc cleanup        убрать всю технику и потерянные сущности всех модулей
```

## Модули

В jar входит шестнадцать модулей. Каждый можно отключить по отдельности в блоке `modules:`
файла настроек, и у каждого есть собственная секция с параметрами движения, вооружения и
модели.

Прочность техники измеряется во взрывах крипера. В настройках хранятся `creeper-damage` и
`creepers-to-destroy`, а полный запас здоровья - это их произведение. Так тюнинг остаётся
наглядным: значение «три» означает, что техника переживает два взрыва в упор и уничтожается
третьим.

### Наземная техника

**Танк** - гусеничная машина с подвижным корпусом, вращающейся башней и поднимающимся
стволом. Корпус доворачивается туда, куда смотрит водитель, а башня наводится независимо.
Танк стреляет баллистическими снарядами, которые разрушают рельеф и повреждают другую
технику; есть перезарядка, блокировка оружия сразу после посадки и перегрев ствола. Заезд в
воду топит экипаж. Максимальная скорость около 18 км/ч, выдерживает четыре взрыва крипера.
Команда: `/tank`.

**КамАЗ «Пушинка»** - тяжёлый бронированный грузовик. Везёт водителя и шесть пассажиров, а
его главная черта - масса: до максимальных 47 км/ч он разгоняется около шести секунд и
поворачивает медленно. На полной скорости отбрасывает существ в стороны, на меньшей -
толкает, не убивая. Вооружения нет, выдерживает три взрыва крипера.
Команда: `/kamaz`.

**Пикап** - лёгкий грузовик с тремя местами: водитель, пассажир и стрелок, который управляет
пулемётом на крыше собственной, независимо наводимой камерой. Любое место может пустовать,
поэтому стрелок в одиночку может вести огонь со стоящего пикапа, а водитель в одиночку -
просто ехать. Ускорение нарастает тем сильнее, чем дольше удерживается газ. Выдерживает
полтора взрыва крипера.
Команда: `/pickup`.

**Мотоцикл** - двухколёсная машина с правой коляской, рассчитанная на водителя, пассажира
сзади и пассажира в коляске. Управляется камерой, как грузовик, разгоняется примерно до
66 км/ч, получает урон при падении и заезжает на ступеньку в один блок. Лимиты установки,
задержки и устойчивый список поставленных мотоциклов хранятся на диске, поэтому счётчики
переживают перезапуск.
Команда: `/moto`.

**Поезд «Desert Express»** - паровоз с тремя вагонами, идущий по обычным ванильным рельсам
единым составом. Сцепка жёсткая, поэтому расстояние между вагонами не растягивается на
поворотах и уклонах. Состав движется с постоянной скоростью девять блоков в секунду без
разгона, плавно тормозит, когда рельсы кончаются, и наносит урон тому, кто стоит на путях.
Пассажиры садятся правым кликом по вагону, в том числе на ходу.
Команда: `/train`.

### Авиация

Вся авиация уничтожается только накопленным уроном. Удар о рельеф наносит повреждения, но
никогда не удаляет аппарат мгновенно.

**Истребитель** - самолёт, управляемый камерой. `W` и `S` отвечают за тягу и торможение,
`A` и `D` вращают машину по крену, `Space` включает форсаж, ограниченный шкалой нагрева
двигателя. Левый клик пускает ракеты, правый сбрасывает бомбы. Реализованы сваливание и
падение. Крейсерская скорость около 115 км/ч, на форсаже заметно выше. Выдерживает два
взрыва крипера.
Команда: `/jet`.

**Вертолёт** - без вертикального ввода висит на месте, как настоящий вертолёт на нулевом
шаге винта. Мышь задаёт курс и подстройку высоты, `W` и `S` двигают вперёд и назад, `Space`
даёт подъём, ограниченный нагревом двигателя. Главный и хвостовой винты вращаются всё время,
пока машина висит. Левый клик пускает ракеты, правый сбрасывает бомбы. Вмещает пилота и трёх
пассажиров, выдерживает два взрыва крипера.
Команда: `/helicopter`.

**Дирижабль** - крупный аппарат легче воздуха, который держит высоту вообще без ввода. Он
намеренно неповоротлив: максимум около 25 км/ч, очень низкое ускорение и медленные широкие
развороты. `Space` включает газовую горелку для подъёма, ограниченную нагревом. Сбрасывает
бомбы, оставляющие стелющийся дым и широкую взрывную волну. Вмещает пилота и двух
пассажиров, уничтожается одним взрывом крипера.
Команда: `/airship`.

**Беспилотник** - аппарат, которым управляют от первого лица. Он летит вперёд сам, будто газ
всё время зажат, и рулится только камерой: смотрите вверх - набирает высоту, вниз - снижается.
Правый клик пускает одну из четырёх одноразовых ракет, левый подрывает боевую часть. Удар
носом о рельеф или цель тоже вызывает подрыв. Двойное нажатие Shift высаживает оператора,
после чего аппарат продолжает лететь прямо, а не падает. Скорость около 122 км/ч,
уничтожается одним взрывом крипера.
Команда: `/drone`, псевдонимы `/bpla` и `/uav`.

### Стационарные установки

**Зенитная установка** - комплекс ближнего боя, который ставится как блок: серый корпус,
белый вращающийся радарный купол и шестиствольная пушка, поднимающаяся по вертикали.
Работает как печь, на топливе: правый клик открывает панель, где загружают топливо и
выбирают режим наведения. Один режим бьёт по враждебным мобам, другой - по игрокам. Стрельба
мгновенная, с разбросом, растущим с дистанцией, и с учётом блоков на линии огня. Установка
ищет цели четыре раза в секунду, доворачивается на 22 градуса за тик и открывает огонь
только после наведения с точностью до семи градусов. Уничтожается лишь взрывным уроном,
рассчитанным на один взрыв крипера.
Команда: `/pvo`, псевдонимы `/antiair`, `/aa`, `/ciws`, `/flak`.

**Артиллерия «Белочка»** - установка навесного огня с полноценной трёхмерной моделью
гаубицы. Оператор входит в камеру над установкой, смотрящую сверху вниз, и вызывает огонь по
реальным координатам мира командой `/shoot x z`. Каждый залп - ровно три снаряда, разброс
растёт с дальностью, поэтому дальние цели поражаются менее точно. В установке три залпа с
двухминутной задержкой между ними. Сессии и состояние установок сохраняются на диск, а защита
блоков не даёт снарядам разрушать защищённый рельеф.
Команды: `/shoot`, `/artillery`.

**Автобус-ловушка** - стационарный автобус с детальной моделью фургона и двумя враждебными
работниками. Работники подходят к ближайшему игроку и бьют его, что ненадолго его
обездвиживает. Если рядом с обездвиженным игроком в пределах четырёх блоков оказываются двое
работников, игрока затягивает в автобус и убивает; иначе он вырывается. Убив обоих
работников, можно сломать сам автобус, и он выдаёт настраиваемый предмет, который оператор
задаёт глобально. Игроки со специальным правом-исключением никогда не становятся целью.
Автобус уничтожается одним взрывом крипера.
Команда: `/tck`, псевдонимы `/tckbus`, `/bus`.

### Авиационная поддержка

**Авиаудар** - предмет-маяк или команда вызывает самолёт, который заходит на бомбометание по
выбранной точке. Он сбрасывает двенадцать зарядов по ковру длиной пятьдесят блоков с центром
в цели, проходя на высоте 75 блоков. Радиус предупреждения оповещает игроков поблизости, а
задержка и лимит одновременных ударов не дают злоупотреблять. Чанки вдоль маршрута
удерживаются загруженными на время удара и освобождаются после.
Команда: `/airstrike`, псевдонимы `/strike`, `/aviaudar`.

**Ядерный удар** - предмет-чемодан или команда отправляет бомбардировщик, который сбрасывает
одну крупную бомбу. Во время медленного падения бомба видна и постепенно разворачивается
носом вниз. При попадании образуются воронка, поднимающееся облако, урон в широком радиусе,
ослепляющая вспышка для наблюдателей и остаточные зоны радиации для выживших. Как и авиаудар,
модуль сам управляет удержанием чанков и освобождает их по завершении.
Команда: `/nuke`, псевдонимы `/nukestrike`, `/yaderka`, `/yadernyudar`.

### Пехотное снаряжение

Модуль снаряжения добавляет около сорока предметов, рассчитанных на раундовый режим или
королевскую битву. Они делятся так.

| Группа | Предметы |
| --- | --- |
| Медицина и расходники | Аптечка, обезболивающее, паёк, боевой стимулятор, ремкомплект |
| Броня и носимое | Бронежилет, кевларовый шлем, экзокостюм, противогаз, наколенники, маскировочная накидка, шлем с визором |
| Огнестрельное | Винтовка, пистолет, гранатомёт, зенитный комплекс, станковый пулемёт, огнемёт, химический распылитель |
| Метательное | Осколочная граната, дымовая, светошумовая, импульсная, коктейль Молотова, усыпляющий газ |
| Устанавливаемое и ловушки | Колючая проволока, растяжка, мина, турель, огневая стена, подрывной заряд, пояс смертника |
| Вспомогательное | Маркер, крюк-кошка, реактивный ранец, сканер разведки, сапёрная лопата |

Несколько особенностей стоит отметить отдельно. Аптечка лечит в течение нескольких секунд, и
любой реальный урон прерывает процесс. Обезболивающее снижает получаемый урон на срок
меньший, чем его собственная перезарядка, поэтому держать эффект постоянно не выйдет.
Бронежилет даёт броню и сопротивление отбрасыванию ценой небольшого замедления. Ремкомплект
сначала чинит технику, в которой сидит игрок, и только потом предмет в руке. Огнестрельное
оружие бьёт мгновенным лучом и повреждает как игроков, так и технику. Значения брони и
атрибутов применяются к предметам, созданным после перезагрузки настроек; уже выданные
предметы сохраняют свои характеристики.

Команда: `/warkit`, псевдоним `/wk`.

### Камера

Вид от третьего лица в Minecraft находится на фиксированном расстоянии за игроком, и для
крупной техники этого мало. Модуль камеры выдаёт сидящему игроку временный атрибут масштаба,
который отодвигает камеру дальше. У каждого типа техники своё значение, поэтому у танка
камера отходит умеренно, а у дирижабля - очень далеко.

Модуль опознаёт технику по scoreboard-тегам, которые модули техники и так проставляют,
поэтому для новой машины достаточно одной строки в настройках. Проверка того, на чём едет
игрок, выполняется четыре раза в секунду.

Поскольку атрибут заодно увеличивает модель игрока и его хитбокс, модули техники скрывают
водителя. Слишком большие значения могут привести к тому, что сидящий в наземной машине
начнёт задевать рельеф, поэтому параметр ограничен диапазоном от 0.0625 до 16.
Команда: `/vehiclecamera`, псевдоним `/vcam`.

## Команды

К каждому модулю есть два пути: собственная команда модуля и общее дерево
`/mc <модуль> <действие>`. Оба варианта выполняют один и тот же код.

### Корневая команда

| Команда | Описание |
| --- | --- |
| `/mc menu` | Открыть графическое меню команд |
| `/mc reload` | Перезагрузить настройки и все активные модули |
| `/mc modules` | Показать все модули и их состояние |
| `/mc cleanup` | Убрать всю отслеживаемую технику и потерянные сущности |
| `/mc <модуль> <действие>` | Выполнить любое действие модуля из списка ниже |

У `/mc` есть псевдоним `/militarycraft`.

Графическое меню заслуживает отдельного упоминания. Оно показывает модули, доступные
смотрящему, затем действия внутри каждого, и отображает только то, к чему у игрока есть
доступ. Действия с параметрами предлагают варианты кликом или запрашивают значение в чате,
поэтому почти всё администрирование можно вести, не набирая команды вручную.

### Команды модулей

| Команда | Псевдонимы | Действия |
| --- | --- | --- |
| `/tank` | | give, spawn, place, remove, cleanup, list, reload |
| `/kamaz` | pushinka, kamazcraft | give, spawn, place, remove, cleanup, list, reload |
| `/pickup` | | give, spawn, place, remove, cleanup, list, reload, migrate |
| `/moto` | motorcycle, bike, motocraft | give, spawn, place, remove, cleanup, list, reload |
| `/train` | poezd | give, place, remove, removeall, list, reload |
| `/jet` | | give, spawn, place, remove, list, reload, cleanup |
| `/helicopter` | heli, verto, vertolet | give, spawn, place, remove, list, reload, cleanup |
| `/airship` | dirizhabl, zeppelin, dirigible | give, spawn, place, remove, list, reload, cleanup |
| `/drone` | bpla, uav | give, spawn, place, fire, exit, remove, list, reload, cleanup |
| `/pvo` | antiair, aa, ciws, flak | give, place, remove, list, reload, cleanup |
| `/tck` | tckbus, bus | give, place, setdrop, cleardrop, showdrop, remove, list, reload, cleanup |
| `/artillery` | artillert | give, create, remove, list, reload |
| `/shoot` | arta | `<x> <z>` - залп по координатам карты |
| `/airstrike` | strike, aviaudar | item, reload |
| `/nuke` | nukestrike, yaderka, yadernyudar | item, reload, place |
| `/warkit` | wk | list, give, giveall, reload |
| `/vehiclecamera` | vcam | reload |

Общие действия работают одинаково во всех модулях:

- `give` создаёт предмет-установщик для этой техники или устройства.
- `spawn` создаёт её на вашей позиции без предмета.
- `place x y z [мир]` создаёт её по точным координатам и работает из консоли.
- `remove` удаляет ту, на которую вы смотрите; `cleanup` убирает оставшиеся сущности.
- `list` показывает, что сейчас загружено и где.
- `reload` перечитывает секцию настроек этого модуля.

Если при выполнении `give` инвентарь игрока полон, предмет выпадает под ноги, а не теряется.

## Права

В MilitaryCraft два уровня контроля доступа, и важно понимать, что первый по умолчанию
перекрывает второй.

### Шлюз команд

По умолчанию `command-access.allow-non-op-commands` имеет значение `false`. В этом состоянии
права у игроков вообще не проверяются: команды MilitaryCraft доступны только операторам,
независимо от того, что выдал плагин прав. Остальным показывается настраиваемое сообщение, а
недоступные команды скрываются из автодополнения.

Поведение настраивают два параметра:

- `honor-admin-permission` (по умолчанию `true`) позволяет не-оператору с правом
  `militarycraft.admin` пройти шлюз наравне с оператором.
- `allowed-non-op-actions` перечисляет действия, которые остаются доступными всем. По
  умолчанию это действия артиллерии и беспилотника, входящие в обычный игровой процесс:
  `artillery.enter`, `artillery.fire`, `artillery.exit`, `drone.fire`, `drone.exit`.
  Они дополнительно проверяются по ситуации: для стрельбы нужна активная сессия артиллерии,
  а действия беспилотника требуют, чтобы игрок действительно им управлял.

Установите `allow-non-op-commands` в `true`, чтобы отключить шлюз и пользоваться обычными
правами Bukkit ровно так, как они объявлены. Именно этот параметр нужно менять, если доступ
раздаётся плагином прав.

### Узлы прав

При открытом шлюзе плагин проверяет следующие узлы.

| Узел | По умолчанию | Что даёт |
| --- | --- | --- |
| `militarycraft.use` | все | Доступ к самой команде `/mc` |
| `militarycraft.menu` | все | Открытие графического меню |
| `militarycraft.admin` | операторы | Все модули и проход через шлюз команд |

У каждого модуля есть своё семейство прав, названное по плагину, из которого он пришёл. Все
они следуют одной схеме: `use` - обычная игра, `place` - установка техники, `give` и
`spawn` - создание предметов и техники, `admin` - удаление, очистка и перезагрузка.

| Семейство | Узлы |
| --- | --- |
| `tankcraft.` | use, drive, place, give, spawn, admin |
| `kamazcraft.` | use, place, give, spawn, admin |
| `pickupcraft.` | use, drive, passenger, gun, place, give, spawn, admin |
| `motocraft.` | use, place, give, spawn, admin |
| `traincraft.` | use, place, give, admin |
| `jetcraft.` | use, place, admin |
| `helicraft.` | use, place, admin |
| `airshipcraft.` | use, place, admin |
| `dronecraft.` | use, place, admin |
| `antiaircraft.` | use, place, admin |
| `tckbus.` | use, place, admin, immune |
| `svoart.` | use, admin |
| `airstrike.` | use, give, reload, bypass-cooldown |
| `nuke.` | use, give, reload, bypass-cooldown |
| `warkit.admin` | Команды снаряжения |
| `vehiclecamera.admin` | Перезагрузка настроек камеры |

`tckbus.immune` - исключение из общей схемы. По умолчанию он не выдан никому и помечает
игроков, которых работники автобуса-ловушки никогда не будут атаковать.

Названия семейств вроде `svoart.` - это исторические идентификаторы исходных плагинов. Их
нужно писать ровно так, как указано, иначе право не сработает.

## Настройка

Плагин использует один файл, `plugins/MilitaryCraft/config.yml`, примерно на 2400 строк. Он
подробно прокомментирован: у каждого значения указаны единица измерения, практический эффект
и, где это полезно, причина выбора значения по умолчанию. Расстояния в блоках, скорости в
блоках за тик, углы в градусах. Один блок за тик равен двадцати блокам в секунду, а умножение
скорости на 72 даёт км/ч - именно эту величину показывает игровой индикатор.

Файл устроен так.

| Секция | Назначение |
| --- | --- |
| `modules` | Включение и отключение каждого из шестнадцати модулей |
| `command-access` | Шлюз команд, описанный в разделе прав |
| `camera` | Расстояние камеры от третьего лица для каждого типа техники |
| По секции на модуль | Все параметры движения, вооружения, модели и прочности |

Чтобы полностью выключить модуль, поставьте флаг и перезагрузите настройки:

```yaml
modules:
  nuke:
    enabled: false
```

`/mc reload` перечитывает файл и передаёт свежие настройки всем активным модулям. Команда
поимённо называет модули, которые не смогли перезагрузиться, а не рапортует об успехе, так
что ошибка в файле видна сразу. Часть значений, например характеристики брони, влияет только
на предметы, созданные после перезагрузки.

Числовые параметры проверяются на диапазон при чтении. Значения вне разумных границ, а также
то, что вообще не является числом, заменяются задокументированным значением по умолчанию,
вместо того чтобы приводить к неработающему поведению.

## Ресурспак

Необязательный ресурспак даёт 38 предметам снаряжения собственные трёхмерные модели. Они
собраны из ванильных текстур блоков, поэтому внутри пака нет ни картинок, ни звуков.

Пользовательские модели по умолчанию выключены и управляются одной настройкой:

```yaml
resource-pack:
  models: false
```

Не включайте её, пока пак реально не раздаётся игрокам. Клиент без пака не умеет откатиться
на обычный вид: неразрешённая ссылка на модель рисуется заглушкой «модель не найдена», а не
исходным предметом. При выключенной настройке предметы просто выглядят как тот ванильный
материал, из которого сделаны, и больше ничего не меняется.

Настройка применяется в момент создания предмета, то есть на уже выданные предметы не
влияет. После изменения выполните `/mc reload` и выдайте предметы заново.

Исходники пака лежат в `resourcepack/warkit/`: описания предметов и моделей плюс файл
`HOW_TO_ENABLE.txt`, где процесс расписан по шагам. Готового архива в репозитории нет,
соберите его сами, заархивировав содержимое этой папки так, чтобы `pack.mcmeta` и
`assets/` оказались в корне архива, а не внутри лишней папки.

Чтобы им пользоваться, разместите zip по прямой ссылке и укажите её серверу в
`server.properties`:

```properties
resource-pack=https://example.com/WarKit.zip
resource-pack-sha1=<sha1 файла>
require-resource-pack=false
```

В Windows хеш считается командой `certutil -hashfile WarKit.zip SHA1`. Игроки также могут
положить zip локально в `.minecraft/resourcepacks`.

Когда пак действительно раздаётся, включите пользовательские модели в настройках и выдайте
предметы заново, потому что ссылка на модель записывается в предмет в момент создания.
Включайте модели только на время раздачи пака, иначе у игроков без него предметы будут
отображаться как отсутствующие модели.

## Сборка из исходников

Нужны JDK 21 и Maven. Единственная зависимость - Paper API, который берётся из репозитория
PaperMC, плюс JUnit для тестов.

```bash
git clone https://github.com/Omny-1/MilitaryCraft.git
cd MilitaryCraft
mvn package
```

Готовый плагин появится в `target/MilitaryCraft-1.0.0.jar`.

Другие полезные команды:

```bash
mvn test                    # прогнать тесты
mvn -DskipTests package     # собрать без тестов
mvn -o package              # собрать офлайн, когда зависимости уже скачаны
```

## Ограничения

Всё перечисленное известно и сделано намеренно - чтобы это не стало неожиданностью.

- Только Paper. Spigot и CraftBukkit работать не будут.
- Folia не поддерживается.
- У техники нет твёрдых столкновений. Игроки и мобы проходят сквозь корпус, а контакт
  определяется по расстоянию, а не по форме модели.
- Слишком большой `camera-scale` заодно увеличивает хитбокс водителя. На наземной машине
  при большом значении водитель начинает задевать рельеф.
- Сессии артиллерии, счётчики мотоциклов и предметы из автобуса хранятся в папке данных
  плагина. Её удаление сбрасывает это состояние.
